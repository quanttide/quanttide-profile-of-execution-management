# 量潮课堂实训基地账本对账

## 需求

审批已作为事实源，为业务系统提供可信记录。业务系统记录需与审批结果对账：比对业务系统记录与审批结果，不一致时以审批为准修正，确保业务系统采用可信记录。

## 目标

以审批为事实源完成对账：业务系统记录与审批结果一致，不一致以审批为准修正。

验收标准：
- [ ] 对账范围覆盖全部业务系统记录
- [ ] 不一致记录均以审批为准修正
- [ ] 对账结果可追溯，业务系统采用可信记录

## 分工

按 RACI 责任矩阵划分（R=执行负责，A=问责，C=咨询，I=知会）：

- **课程主管**：授权型上级——决策权下放给问责人（全栈工程师），只授权并看结果，不直接参与事务；全程仅被知会（I）
- **全栈工程师**：负责人——全过程问责（A）并获得决策权，决策/计划/执行亲自执行（R）；评审阶段咨询（C）
- **产品经理**：复核/评审人——评审阶段执行验收（R）；其余阶段咨询（C）
- **课程助教**：不在本任务内，仅被知会（I）——审批为业务系统侧已完成工作

### 1. 决策

全栈工程师决定做账本对账：以审批为事实源，确保业务系统记录可信。

### 2. 计划

全栈工程师负责制定对账方案：比对业务系统记录与审批结果，不一致时以审批为准修正。

### 3. 执行

全栈工程师执行对账：比对业务系统记录与审批结果，不一致时以审批为准修正。

### 4. 评审

产品经理负责验收：核对对账结果与审批记录，确认修正无误。

### 5. 复盘

回顾对账全流程，改进对账规则，沉淀为业务系统可信记录基线。
