# QtCloud 媒体云任务分解

分解自 [index.md](index.md) 的「媒体云」任务组：index 只留当前状态，任务细节与叙事记在本文件，完成后回写 index。产品代码在 quanttide-media 域 `apps/qtcloud-media`，含命令行工具（CLI）、工作台（studio）、服务端（provider）三个组件与小红书图集生成器。

## 对应关键结果

把媒体云从原型变成生产可用上线，并获取第一个外部付费客户。

## 当前状态

三个组件都已过首版，进入 v0.1–0.2 验证迭代：CLI 最新 0.2.0（2026-11-01 发布，命令树按 article、note、config 重组），工作台最新 0.1.3（Web 与 Linux 桌面，远程推公众号已通），provider 0.1.0 已完成真实公众号端到端首验（草稿推入、再更新同一篇）。工作台的部署链路已配好，打 `studio/*` 标签即部署到 `studio.media.cloud.quanttide.com`；provider 缺省只监听本机 127.0.0.1:8787，尚未云端部署。两项关键结果均未达成。

## 任务

### 验证与迭代 v0.1–0.2

当前任务组，按依赖顺序推进三件事：

1. 发布工作台的未发布改动：侧边导航（文章、图文、视频、设置）、详情工具带、删除草稿、小红书图集入口。
2. 发布 provider 的未发布改动：历史文章接口（`GET /articles`）与封面类型嗅探，打通 CLI `article pull` 的新数据来源。
3. 回归验证 CLI 0.2.0 的命令树重组——旧命令不留别名，逐条核对 article、note、config 三组的迁移，同时验证小红书图集链路（工作台工具带调 CLI `note export`）。

### 生产可用上线

工作台的部署链路已具备（Actions 构建、OSS 托管、CDN 分发），按 `manifests/terraform/README.md` 的首次上线步骤走通并验证域名可访问。provider 目前只有本机监听，需要先定部署形态再上线。

### 获取第一个外部付费客户

尚未启动，依赖生产可用上线后的真实使用；获客动作确定后回写本节。
